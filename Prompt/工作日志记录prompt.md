
请为当前项目建立并持续维护**本地工作日志**，同时避免日志持续增长而占用过多上下文。

## 1. 初始化

在项目根目录创建以下结构：

```text
.codex/
└── work-journal/
    ├── current.md
    └── archive/
        └── YYYY-MM.md
```

将 `.codex/` 加入项目根目录的 `.gitignore`，确保该目录不会被提交到远程仓库：

- 如果 `.gitignore` 不存在，请创建它。
- 如果忽略规则已存在，请不要重复添加。

## 2. 文件用途

### `.codex/work-journal/current.md`

仅保存继续工作所必需的最新状态：

- 当前任务与目标
- 关键进展
- 重要决策及原因
- 已知问题或阻塞项
- 未完成事项
- 下一步行动

该文件应控制在 **200 行以内**。更新时可以删除或合并过时信息，但必须保留后续工作仍需使用的内容。

### `.codex/work-journal/archive/YYYY-MM.md`

按月保存详细工作历史。完成一个重要阶段或结束工作前，将本次记录追加到当月文件末尾，不要覆盖已有记录。

## 3. 工作流程

### 开始工作时

1. 只读取 `.codex/work-journal/current.md`，了解当前状态。
2. 不要默认读取全部历史日志。
3. 只有在排查历史问题或缺少必要背景时，才按需读取 `.codex/work-journal/archive/` 中的相关记录。

### 完成阶段或结束工作前

1. 更新 `.codex/work-journal/current.md`，使其准确反映最新状态。
2. 将本次工作的记录追加到 `.codex/work-journal/archive/YYYY-MM.md`。
3. 保持内容简洁，不重复记录可直接从 Git diff、提交历史或代码中获取的细节。
4. 不要记录密码、Token、密钥或其他敏感信息。

## 5. 月度日志格式

只保留本次实际需要的栏目；没有内容的栏目可以省略。

```markdown
## YYYY-MM-DD HH:mm｜任务简述

### 目标
- 

### 已完成
- 

### 关键文件
- `relative/path/to/file`

### 决策与原因
- 

### 问题与解决办法
- 问题：
  - 原因：
  - 解决办法：

### 遗留事项
- [ ] 
```

## 6. 日志内说明

初始化时，在 `.codex/work-journal/current.md` 开头加入一段精简说明，提醒后续工作遵守以下原则：

> 开始工作时只读取本文件；仅在必要时按需查阅 `archive/`。结束工作前更新本文件，并将详细记录追加到当月日志。本文件须保持精简且不超过 200 行，不得记录敏感信息。

完成初始化或日志更新后，请简要说明本次新增或更新了哪些内容。

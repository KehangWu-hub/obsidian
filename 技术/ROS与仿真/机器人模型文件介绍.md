本文介绍 URDF、STL、DAE、MJCF、YAML 等机器人模型相关文件。

# 先看结论

**URDF/MJCF/SDF 描述模型关系，STL/DAE 提供网格外形，XML 是它们可能采用的语法，YAML 保存程序参数。**

一套机器人模型通常不是单个文件，而是多个文件共同组成：

```text
robot_description/
├── robot.urdf             机器人结构
├── meshes/                连杆的三维外形
│   ├── base.stl
│   └── arm.dae
└── controllers.yaml       控制器参数
```

# 网格文件

STL 和 DAE 都可以保存连杆的三维网格。它们只描述零件的外形，不知道零件之间如何连接，也不包含完整的关节、质量和控制信息。

## STL

STL 主要保存由三角面组成的几何外形，格式简单、兼容性好，常用于单色显示模型和碰撞模型。

STL 通常不保存材质、纹理和可靠的单位信息。因此，使用 STL 时需要特别检查模型比例，避免毫米和米混用导致尺寸相差 1000 倍。

## DAE

DAE 是 COLLADA 格式。除了网格，它还可以保存颜色、材质、纹理引用、单位和坐标变换，更适合作为显示模型。

DAE 的内容比 STL 丰富，但结构也更复杂。不同软件对其中的材质、纹理和坐标变换支持可能不完全一致。

## 两者的选择

| 对比项   | STL       | DAE      |
| ----- | --------- | -------- |
| 几何外形  | 支持        | 支持       |
| 颜色与材质 | 通常不包含     | 可以包含     |
| 纹理    | 不支持       | 可以引用     |
| 格式复杂度 | 低         | 较高       |
| 常见用途  | 碰撞模型、单色显示 | 带材质的显示模型 |

建模软件导出 STL 还是 DAE，通常取决于是否需要保留材质，并不是 URDF 规定必须使用哪一种。

如果 STL 和 DAE 来自同一个零件，并且导出时的比例、坐标和网格精度一致，那么模型轮廓可以基本相同。区别主要体现在颜色、纹理、单位信息以及不同软件的兼容性上。

实际项目中经常使用 DAE 作为 `visual` 显示网格，使用简化后的 STL 作为 `collision` 碰撞网格。这不是强制要求，二者也可以都使用 STL。

# 机器人描述文件

网格文件只提供外形，机器人描述文件负责把这些外形组织成完整的机器人。

## URDF

URDF 是 ROS 中常用的机器人描述格式，主要包含：

- `link`：机器人由哪些连杆组成。
- `joint`：连杆之间如何连接和运动。
- `visual`：显示时使用什么几何体或网格。
- `collision`：碰撞检测使用什么几何体或网格。
- `inertial`：质量、质心和惯量。

复杂连杆的外形通常不会直接写进 URDF，而是引用外部 STL 或 DAE：

```xml
<link name="arm_link">
  <visual>
    <geometry>
      <mesh filename="package://my_robot/meshes/arm.dae"/>
    </geometry>
  </visual>
</link>
```

因此，`URDF + STL` 和 `URDF + DAE` 的整体结构相同，只有 URDF 引用的网格格式不同。网格文件如果丢失，URDF 中的连杆和关节信息仍然存在，但复杂外形无法正常显示。

## XML语法

XML 是一种组织文本的语法，不是专门的机器人模型格式。URDF、MJCF 和 SDF 都使用 XML 语法，但它们规定的标签和含义不同。

可以通过根标签初步判断文件遵循哪种规范：

```xml
<robot name="demo">       <!-- URDF -->
<mujoco model="demo">     <!-- MJCF -->
<sdf version="1.12">      <!-- SDF -->
```

文件扩展名也不能完全代表内容。URDF 通常使用 `.urdf`，MJCF 通常直接使用 `.xml`，但两者本质上都是 XML 文本。把 `.urdf` 改名为 `.xml` 不会将它转换成 MJCF。

## Xacro

Xacro 是用于生成 URDF 的 XML 宏语言。它支持变量、宏、条件和文件包含，适合拆分大型模型或复用重复结构。

```text
robot.urdf.xacro ──展开──> URDF ──读取──> RViz、ROS 2 或仿真器
```

Xacro 最终仍要生成 URDF，它本质不是另一种格式。

## MJCF

MJCF 是 MuJoCo 原生的模型描述格式，通常使用 `.xml` 扩展名。它可以描述刚体、关节、碰撞、执行器、传感器、约束和仿真参数。

MuJoCo 可以读取部分 URDF 模型，但 URDF 无法完整表达 MuJoCo 的全部功能。需要细致配置执行器、接触、传感器或约束时，通常会将模型整理为 MJCF。MJCF 仍然可以引用外部网格文件。

## SDF

SDF 是 Gazebo 常用的仿真描述格式，同样使用 XML 语法。除了机器人，它还可以描述世界、灯光、传感器、物理参数和插件。

ROS 项目通常维护 URDF/Xacro，Gazebo 在加载时可以将其转换为 SDF。需要完整描述 Gazebo 世界或使用更多 Gazebo 专属功能时，则会直接编写 SDF 或 `.world` 文件。

# YAML 配置文件

YAML 不保存机器人外形或结构，而是保存程序运行参数。例如：

- `ros2_control` 使用哪些控制器。
- 控制器负责哪些关节。
- 控制频率和接口参数。
- MoveIt、Nav2、SLAM 或其他 ROS 2 节点的配置。

```yaml
controller_manager:
  ros__parameters:
    update_rate: 100
    arm_controller:
      type: joint_trajectory_controller/JointTrajectoryController
```

URDF/Xacro 描述机器人本体，YAML 配置控制机器人或使用机器人模型的程序，两者相互配合。

# 常见使用场景

## ROS 2 与 RViz

```text
URDF/Xacro + STL/DAE
```

URDF/Xacro 描述机器人结构，STL/DAE 提供复杂外形，RViz 负责显示模型和 TF。

## ROS 2 与 Gazebo

```text
URDF/Xacro + STL/DAE + YAML
                    │
                    └── 控制器与插件参数
```

Gazebo 会使用或转换机器人描述，并结合自己的 SDF、世界和插件配置进行物理仿真。

## MuJoCo

```text
MJCF（.xml）+ STL/其他受支持的网格
```

MJCF 描述 MuJoCo 中的模型和仿真属性，网格文件只负责提供复杂几何外形。
